# Product Searcher — Project Context

## Overview
Flutter app. Single feature implemented: **auth**. The project is portfolio-oriented, showcasing a production-quality authentication system with Clean Architecture.

## Tech Stack
- Flutter + Dart (SDK ^3.11.1)
- Firebase (firebase_core ^4.6.0, firebase_auth ^6.3.0, cloud_firestore)
- Google Sign-In **7.2.0** — uses new singleton API (`GoogleSignIn.instance`, `.initialize()`, `.authenticate()`)
- State management: **Riverpod 3.x** (`flutter_riverpod ^3.3.1`) + **riverpod_generator** (`riverpod_annotation ^4.0.2`, `riverpod_generator >=4.0.1 <5.0.0`) — all providers use `@Riverpod` annotations; generated files committed to repo
- Functional error handling: **dartz** (`Either<Failure, T>`)
- Value equality: **equatable** (`equatable ^2.0.7`) — `Failure` extends `Equatable`, removes manual `==`/`hashCode`
- Immutable models/states: **freezed** + **json_serializable** (code-gen via build_runner)
- Testing: mocktail

## Provider Chain (auth_providers.dart + auth_notifier.dart)
All providers use `riverpod_generator` (`@Riverpod(keepAlive: true)`). Generated files: `auth_providers.g.dart`, `auth_notifier.g.dart`.
```
firebaseAuthProvider  ──┐   (auth_providers.g.dart)
firestoreProvider     ──┴─ authRemoteDataSourceProvider
                               └─ authRepositoryProvider
                                    ├─ signInWithGoogleUseCaseProvider
                                    ├─ signInWithEmailUseCaseProvider
                                    ├─ signUpWithEmailUseCaseProvider
                                    ├─ signOutUseCaseProvider
                                    └─ getCurrentUserUseCaseProvider
                                         └─ authProvider  (NotifierProvider<AuthNotifier, AuthState> — auth_notifier.g.dart)
```
Note: `authProvider` is the generated name for `AuthNotifier` (riverpod_generator 4.x strips the `Notifier` suffix). Infrastructure providers use `keepAlive: true`; use case providers use `@riverpod` (auto-dispose).

## Key Implementation Notes
- Google Sign-In 7.2.0 breaking changes: `GoogleSignIn.instance.initialize()` must be called before `authenticate()`. `authenticate()` throws `GoogleSignInException` on cancel. `idToken` only (no `accessToken`) for Firebase credential.
- `AuthRepositoryImpl` maps `FirebaseAuthException` → `AuthFailure`, `GoogleSignInException` → `GoogleSignInFailure`, generic `Exception` → `ServerFailure`.
- `AuthNotifier.build()` calls `getCurrentUser()` synchronously to hydrate state on startup (handles app restart with active session).
- `AuthWrapper` watches `authProvider` directly and pattern-matches on `AuthState` — no separate stream provider. `authProvider` is the single source of truth for auth state.
- `AppCupertinoTextField` exists because `CupertinoTextField` does not implement `FormField` (no `validator` support) and `CupertinoTextFormFieldRow` lacks a `suffix` prop. Solution: `TextFormField` styled to match iOS aesthetics.
- `SocialColors` in `app_colors.dart` centralises Google branding tokens (bg, outline, text for light/dark), consumed by `google_sign_in_button.dart`.
- Freezed `.freezed.dart` and `.g.dart` files are generated — run `dart run build_runner build` after model changes. Generated files are committed to the repo.
- Theme: adaptive (Material for Android, Cupertino-style widgets on iOS). Cupertino text themes (`lightCupertinoTextTheme` / `darkCupertinoTextTheme`) defined in `AppTextStyles`, consumed by `AppTheme.cupertinoLight` / `cupertinoDark`.

## Key Widgets
- `auth_illustration.dart`: Animated lock illustration (float + glow pulse, `TickerProviderStateMixin`). Used in `auth_header.dart`.
- `app_cupertino_text_field.dart`: `TextFormField` with iOS-style decoration (`surfaceContainerHighest` fill, rounded border). Used by `AdaptiveTextField` on the Cupertino path.
- `google_sign_in_button.dart`: Uses `flutter_svg ^2.0.10+1` with the official Google G SVG embedded as `_googleLogoSvg`. Colors sourced from `SocialColors`. `flutter_signin_button` was removed — incompatible with `font_awesome_flutter` v11.
- Password validation in `register_screen.dart`: ≥8 chars, uppercase, digit, special char (`[!@#$%^&*()\-_=+\[\]{};:,.<>?/\\|~]`).
